Project Overview

SAT-1 is a space-themed embedded system developed on the ESP32-S3 using FreeRTOS. A pushbutton connected to GPIO18 simulates a ground command sent to a satellite. Pressing the button generates a hardware interrupt that activates a minimal Interrupt Service Routine.

The ISR signals two bottom-half tasks using a Binary Semaphore and a Direct Task Notification. Their wake-up latency is measured under idle and loaded processor conditions using the Wokwi Logic Analyzer.

Application 5 runs as the system spine. Its interrupt-driven command path is the backbone of SAT-1, extended with the interrupt and synchronization work from Application 3 and the periodic background tasks from Application 2. Those background tasks create processor load during interrupt testing, so the integrated system demonstrates interrupt handling, task synchronization, scheduling, timing analysis, and engineering documentation in one coherent product.

System Architecture

System Flow

The ISR responds immediately to the GPIO18 falling edge and performs only ISR-safe operations. It records a timestamp, applies debounce protection, generates a GPIO19 timing pulse, and signals both bottom-half tasks.

Longer processing and reporting are deferred to FreeRTOS task context. The Binary Semaphore and Direct Task Notification paths are measured separately so their wake-up behavior can be compared.

Schedulability

The four periodic load tasks use fixed-priority preemptive scheduling with priorities assigned in rate-monotonic order, and each deadline equals its period. The rate-monotonic bound for n = 4 independent periodic tasks is n(21/n − 1) = 0.757. The two event-driven bottom-half tasks are excluded from the periodic utilization sum because they are aperiodic. They are bounded instead by the measured wake-up latency reported below.

Hazard Analysis

Hazards are mapped to IEC 61508, the functional-safety standard for electrical, electronic, and programmable electronic safety-related systems. Part 3 covers software requirements; Part 7 covers techniques and measures.

Hazard Effect Mitigation Standard mapping
Long ISR execution Increased interrupt latency Keep the ISR minimal and defer processing IEC 61508-3 §7.4.3 — bounded response time
Button bounce Repeated interrupt events Apply timestamp-based debounce logic IEC 61508-7 — input signal conditioning
Missing scheduler yield Delayed bottom-half execution Use portYIELD_FROM_ISR() IEC 61508-3 §7.4.4 — defensive programming
Heavy processor load Increased bottom-half latency Use fixed-priority scheduling and timing verification IEC 61508-3 §7.4.4 — deterministic scheduling
Non-ISR-safe function call Unpredictable behavior or system failure Use only ISR-safe FreeRTOS APIs inside the ISR MISRA C:2012 Dir 4.1 — run-time failure avoidance

Fault Injection and Graceful Degradation

Fault Introduced

The scheduler-yield call was temporarily removed from the ISR: 

// portYIELD_FROM_ISR(higher_woken);

Prediction

The ISR should continue delivering both signals, but the awakened bottom-half tasks might not run immediately after the ISR returns. Their response was expected to become slower and less deterministic.

Observation

Interrupts continued to be detected, and both bottom-half tasks still executed. However, their wake-up timing became less immediate and less predictable.

Recovery

The line was restored in the final working implementation: 

portYIELD_FROM_ISR(higher_woken);

The system therefore degraded in timing performance rather than failing completely. Interrupt detection and event delivery remained operational throughout the experiment.
