One-Sentence Theme

An interrupt-driven satellite ground command system that uses FreeRTOS top-half and bottom-half processing to provide bounded response to spacecraft events, demonstrating real-time embedded system design for an Entry-Level Electrical Engineer role.

Project Overview

SAT-1 is a space-themed embedded system developed on the ESP32-S3 using FreeRTOS. A pushbutton connected to GPIO18 simulates a ground command sent to a satellite. Pressing the button generates a hardware interrupt that activates a minimal Interrupt Service Routine.

The ISR signals two bottom-half tasks using a Binary Semaphore and a Direct Task Notification. Their wake-up latency is measured under idle and loaded processor conditions using the Wokwi Logic Analyzer.

The capstone builds on Application 3 while incorporating periodic background tasks from Application 2. This creates processor load during interrupt testing and demonstrates interrupt handling, task synchronization, scheduling, timing analysis, and engineering documentation in one complete project.

The ISR responds immediately to the GPIO18 falling edge and performs only ISR-safe operations. It records a timestamp, applies debounce protection, generates a GPIO19 timing pulse, and signals both bottom-half tasks.

Longer processing and reporting are deferred to FreeRTOS task context. The Binary Semaphore and Direct Task Notification paths are measured separately so their wake-up behavior can be compared.

Hazard Analysis

Hazard Effect Mitigation
Long ISR execution Increased interrupt latency Keep the ISR minimal and defer processing
Button bounce Repeated interrupt events Apply timestamp-based debounce logic
Missing scheduler yield Delayed bottom-half execution Use portYIELD_FROM_ISR()
Heavy processor load Increased bottom-half latency Use fixed-priority scheduling and timing verification
Non-ISR-safe function call Unpredictable behavior or system failure Use only ISR-safe FreeRTOS APIs inside the ISR

Fault Injection and Graceful Degradation

Fault Introduced

The scheduler-yield call was temporarily removed from the ISR: 

// portYIELD_FROM_ISR(higher_woken);

Prediction

The ISR should continue delivering both signals, but the awakened bottom-half tasks might not run immediately after the ISR returns. Their response was expected to become slower and less deterministic.

Observation

Interrupts continued to be detected, and both bottom-half tasks still executed. However, their wake-up timing became less immediate and less predictable.

Recovery

The line was restored in the final working implementation: 

portYIELD_FROM_ISR(higher_woken);

The system therefore degraded in timing performance rather than failing completely. Interrupt detection and event delivery remained operational throughout the experiment.

Build and Run

  1. Open the linked Wokwi project.
  2. Start the ESP32-S3 simulation.
  3. Open the Serial Monitor.
  4. Press the GPIO18 pushbutton.
  5. Observe the semaphore and notification latency results.
  6. Set WITH_LOAD to 1 to repeat the test with the Application 2 background workload.
  7. Use the Wokwi Logic Analyzer to capture the GPIO18 and GPIO19 timing signals.
